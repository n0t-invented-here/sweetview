WT.5 evidence: the web-app page in a real Tauri 2 shell
=========================================================

Machine: Windows 11 Pro 10.0.26300 x64, WebView2 Runtime 158.0.4370.33.
Tools: Bun 1.4.4, just 1.58.0, rustc 1.97.1, cargo 1.97.1.
Paths below: <REPO> is the repository root.
Tauri 2.12.7 (crate), tauri-cli 2.12.6, webview2-com 0.39.1, from demos/web-app-tauri.

What ran
--------
From <REPO>:

    just demos::web-app-tauri::probe

The recipe builds the unchanged web-app page from demos/web-app/packages/web-app-frontend
through demos/web-app-tauri/index.html (bridge.ts picks tauriTransport() because the page runs
in a Tauri webview), writes the icon, runs `tauri build --debug --no-bundle` (Cargo, with
src-tauri's own empty [workspace]), and starts the built executable with WEB_APP_PROBE=1.
The backend is Rust (src-tauri/src): the sweetview_ipc command decodes each CallFrame and
returns the ReplyFrame; events go out as the Tauri event sweetview-ipc:event carrying an
EventFrame. With WEB_APP_PROBE=1 the Rust side logs each call and event ("host: ..."), and
once the page has loaded evaluates demos/web-app/scripts/shell-probe.js in the page; the
page sends its report back through the probe_report command, which prints the PROBE line
and exits. Exit code: 0.

What was seen
-------------
- Method: the page called info.get; the Rust backend's reply, rendered in the page's Runtime
  card, reads Host "Tauri 2, Rust backend, 1 session", Runtime "Rust backend, Tauri 2.12.7",
  Platform "Windows / x64". The header badge reads "Tauri 2 · IPC". The page was served from
  http://tauri.localhost/.
- Event: the probe typed a note into the page's form and clicked Add. The page called
  notes.add; the Rust backend emitted notes.changed to every webview; the new note appeared
  in the page's list 56 ms after the click, and the count badge went from 2 to 3. The page
  renders the list only from the notes.changed event, so the note on screen is the event
  received.
- Targeted events: a separate check build (not committed) registered two listeners in the
  page through __TAURI_INTERNALS__, one scoped to webview "main" (what tauriTransport()
  registers) and one scoped to a webview "other", then invoked watch.stop (whose watch.status
  event the backend sends with emit_to to webview "main" only) and notes.add (broadcast).
  Result: {"mine":["watch.status","notes.changed"],"other":["notes.changed"]}: the targeted
  event reached only the webview it was sent to.

A screenshot of the same window, taken separately, showed the page fully rendered with the
same values; the text above is the evidence.
