W7.1. Tabs on Windows: every behaviour of "Behaviour: tabs on Windows"
(rust-rewrite/reference/v1-drafting-tabs-and-window.md), clause by clause,
and the check that proves each on the final tree.

Every command below ran in <REPO> with WEBVIEW2_USER_DATA_FOLDER set to a
fresh folder under <TEMP>, so no run shared a WebView2 profile with another
session on the machine.

Where the checks live:
  F  = packages/sweetview/test/fixtures/win-tabs.ts (run by
       packages/sweetview/src/tabs/win-tabs.test.ts, "tabbed windows (win32, live)")
  I  = packages/sweetview/test/fixtures/win-tabs-input.ts (run by the same test file,
       "tabbed windows: strip gestures and real keys (win32, live)"): real input
  P  = packages/sweetview/test/fixtures/win-menu-probe.ts, the second process that
       reads and works a popup menu for F (now also by command id: pick-id:<id>)
  R  = crates/sweetview-platform-window/src/tab_frame_tests.rs (cargo test)
  W  = packages/sweetview-native/src/win32/window.test.ts ("win32 Window")
  A  = packages/sweetview/src/app.test.ts ("WebView & createApp (win32)")
  S  = packages/sweetview-native/src/win32/strip-shared.test.ts and shortcuts.test.ts
  D  = demos/native-tabs/scripts/win-drive.ts (just demos native-tabs drive)

A check the fixture records as skipped (the shared desktop was not the
fixture's: a mouse button held by another session, another window over the
fixture's, the foreground taken) shows as (skip) in the runner, never as a
pass, and win-tabs.test.ts prints one line per fixture with how many checks
ran, passed, failed and were skipped.

== The frame: decisions this item rests on ======================================

- The frame is tao's window with with_decorations(false) and
  with_undecorated_shadow(true): the system keeps its border, shadow, snap,
  maximise and system menu; no WM_NCCALCSIZE handling of this project's, and
  its class is tao's, not SweetviewTabFrame.
- The backdrop and a DPI change are answered by a second subclass procedure of
  the frame (FrameMessages in crates/sweetview-platform-window/src/tab_frame.rs).
- The tab context menu is this project's own synchronous popup
  (TrackPopupMenu with TPM_RETURNCMD), and activation comes from the existing
  window subclass.

== A product defect this item's checks found, and its fix =============================

20h. A navigation of a URL tab to an about: address the engine refuses showed
the failed-load page, naming the tab's first address. WebView2 rewrites an
about: address other than about:blank and about:srcdoc to edge://<name>/
before the navigation starts, and NavigationStarting reports that address, so
failure_reason (crates/sweetview-platform-webview/src/lib.rs) saw no about:
prefix. It now leaves out the edge: and chrome: schemes as well as about:, with
a unit assertion beside it, and the check "failed load: not shown for an about:
address the engine refuses" passes in the run below.
