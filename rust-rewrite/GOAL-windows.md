Rewrite Sweetview's native layer for Windows as type-safe Rust reached from Bun through N-API, with no functionality removed. Repository `n0t-invented-here/sweetview`, branch `v1-rust-rewrite`.

READ FIRST, in full, and again after every context compaction: `rust-rewrite/REQUIREMENTS.md`, `rust-rewrite/UNSAFE-POLICY.md`, `rust-rewrite/CHECKLIST-windows.md`, `rust-rewrite/FORKS.md`, `SWEETVIEW-RESTART-PROPOSAL.md`. `rust-rewrite/reference/` says what today's code does, file by file. `rust-rewrite/spike/` is the working proof of the N-API mechanisms.

OUTCOME. The branch today is `main` with `v1-drafting` merged: a TypeScript `bun:ffi` native layer over a C++ webview library. The result is the same product, same API, same behaviour, with all native code in Rust on `tao`, `wry`, `muda`, `tray-icon`, `rfd` and `napi`, plus `windows` and `webview2-com` for what this project writes itself. On Windows no Sweetview package calls `bun:ffi`, and the C++ library and `@n1h/sweetview-webview-bun` are gone.

SCOPE. Everything is in scope. Nothing is declared out of scope, deferred, stubbed or dropped. That covers every export and documented behaviour of Sweetview's packages, of the Bun bindings (`n0t-invented-here/sweetview-webview-bun`, branch `v1-drafting`) and of the C++ fork's additions (`n0t-invented-here/sweetview-webview`, branch `v1-drafting`): transparent click-through overlays with hit regions, system-wide mouse and keyboard hooks, tray, menus, notifications, dialogs, tabs, the request handler, streaming, file drop, activation, both event-loop modes, packaging and `bun build --compile`. A behaviour no crate provides is written by this project in Rust. Every existing application keeps a full upgrade path with no behaviour lost: `docs/upgrading.md`, the tests under `rust-rewrite/compat/`, and the dependents run of R2.

QUALITY. Memory safety is the purpose. Safe crate APIs come first; `unsafe` lives only in `crates/sweetview-platform` under `UNSAFE-POLICY.md`; an owning type with `Drop` holds every OS resource. Rust that wraps the old calls in `unsafe` blocks fails this goal.

PRIVACY. Applications that depend on Sweetview are private. Their names, paths, code and behaviour never enter a tracked file, a commit message, a branch, a tag or anything pushed (R6).

METHOD. Do the checklist groups in order. Tick an item only after running its acceptance and pasting the output under it.
